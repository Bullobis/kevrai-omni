## 二、为什么门槛是 65% 而不是 80%

CI 原先写的门槛是 80%，但**实测只有 66.5%，意味着 python job 从建立起就必然是红的** ——
一个永远失败的检查等于没有检查，只会让人学会忽略它。

现在的做法是把门槛设在**实测基线略下方（65%）**，职责明确为「防止覆盖率倒退」，
同时用 `::warning::` 提示距 80% 目标还有多远。**随着覆盖率真实提升再上调门槛，
不允许把门槛抬到实际值之上。**

## 四、优先级建议

### P0：缺口大户（单模块 > 150 行）

| 模块 | 缺口 | 说明 |
|------|------|------|
| `app/main.py` | 809 | FastAPI 路由定义。大量是路由注册样板，可先用 pytest 客户端做冒烟式覆盖，收益快 |
| `app/converter.py` | 309 | 格式转换。纯函数逻辑，输入输出明确，最容易写单测 |
| `app/mnn_runtime.py` | 217 | MNN 引擎适配。需 mock 外部进程调用 |
| `app/drama.py` | 193 | 短剧生成流程。副作用多，需先理清依赖边界 |

**只补 `converter.py` + `mnn_runtime.py` + `drama.py` 三个（719 行）
就能把总覆盖率推到约 74.7%**，是性价比最高的一步。

## 五、推进节奏

不建议一次性投入数天冲 80%。建议按发布周期分批：

1. **每个版本补 150–250 行覆盖** —— 约 5–8 个用例文件，工作量可控
2. 优先补 **P0 的纯逻辑模块**（`converter.py` 最优先）
3. 每补一批就把 CI 门槛上调到新的实测值下方 1–2 个百分点
4. 覆盖率不再倒退的前提下，约 5–6 个版本可到 80%

## 六、如何本地复现

```bash
cd python
pytest -q tests/ --cov=app --cov-report=term-missing
```

查看具体哪一行没覆盖，把 `term-missing` 换成分模块报告：

```bash
pytest -q tests/ --cov=app --cov-report=term-missing \
  --cov-report=html:htmlcov
# 打开 python/htmlcov/index.html
```
